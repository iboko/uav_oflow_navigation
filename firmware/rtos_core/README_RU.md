# RTOS-ядро навигации БВС по оптическому потоку

Этот каталог содержит бортовое C++17-ядро для режима полета БВС по данным оптического потока. Python-код верхнего уровня остается инструментом для SITL, генерации данных, анализа логов и проверки гипотез. Детерминированная часть, которую можно переносить в PX4/NuttX, ArduPilot/AP_HAL или другую RTOS-среду, вынесена в `firmware/rtos_core`.

## Что реализовано

1. Преобразование `OPTICAL_FLOW_RAD` + дальномера + IMU в горизонтальную скорость.
2. Учет высоты по дальномеру с компенсацией крена и тангажа.
3. Компенсация вращательного движения по интегральным гироскопам ОП.
4. Учет рычага установки датчика: `v_sensor = v_cg + omega x r_sensor`.
5. Матрица ориентации датчика относительно корпуса: `body_from_sensor`.
6. Масштабы ОП по осям: `flow_scale_x`, `flow_scale_y`.
7. Горизонтальный EKF с состоянием `[n, e, vn, ve, bax, bay]`.
8. Проверка инновации по критерию `y^T S^-1 y`.
9. Safety state machine: `FLOW_NAV`, `DEGRADED_HOLD`, `FAILSAFE_LAND`.
10. CMake-сборка и автономные тесты без внешних библиотек.

## Почему это RTOS-ориентированный код

- нет исключений в интерфейсе;
- нет `new`, `delete`, STL-контейнеров с динамической аллокацией в цикле;
- фиксированные матрицы и структуры;
- все входные сообщения имеют timestamp;
- интерфейс не зависит от Linux, ROS, pandas, NumPy или MAVSDK;
- можно вызывать из периодической RTOS-задачи;
- можно обернуть в PX4-модуль или ArduPilot backend.

## Сборка

```bash
cmake -S firmware/rtos_core -B build/rtos_core -DOFNAV_BUILD_TESTS=ON
cmake --build build/rtos_core
ctest --test-dir build/rtos_core --output-on-failure
```

## Главный интерфейс

```cpp
ofnav::Config cfg{};
cfg.sensor_offset_body_m = {0.10F, 0.0F, 0.0F};
cfg.flow_scale_x = 1.0F;
cfg.flow_scale_y = 1.0F;

ofnav::OfNavRuntime runtime(cfg);

ofnav::RuntimeOutput out = runtime.step(imu, range, flow, attitude);

if (out.mode == ofnav::NavMode::FlowNav) {
    // Использовать out.state.vn_m_s / out.state.ve_m_s в контуре САУ
}
```

## Что еще требуется до реального полета

Этот модуль — профессиональное ядро навигационного режима, но не полная сертифицированная авионика. Для допуска к реальному полету необходимо добавить:

1. аппаратный драйвер конкретного датчика ОП;
2. драйвер дальномера и проверку его ориентации;
3. интеграцию с PX4 uORB или ArduPilot AP_HAL;
4. журналирование в штатный лог автопилота;
5. параметризацию через систему параметров автопилота;
6. HIL/SITL-проверки с задержками и отказами;
7. летную методику с ограничением углов, скорости и высоты;
8. независимый ручной перехват внешним пилотом.
