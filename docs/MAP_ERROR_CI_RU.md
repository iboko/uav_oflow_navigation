# Оценка погрешностей картографической привязки и ковариационное пересечение

**Статус:** исследовательский офлайн-этап после PR #12. Не является
завершенной VIO, не подключается в PX4 и не выдает разрешений на
управление БВС.

## 1. Раздельная оценка на независимых полетах

Входные данные — кандидат положения по ортофотоплану и независимый
эталон координат в **одной метрической СК N/E и в одинаковый момент
времени**. `run_map_error_calibration.py` принимает два
непересекающихся множества полетов:

- `train` — только для оценки смещения и ковариации
- `holdout` — только для проверки модели после настройки

Обозначим ошибку `e_k = p_map,k - p_ref,k`. По обучающим
полетам с равным весом каждого полета вычисляются:

```text
b = mean_flight( mean_frames(e_k) )
R = mean_flight( mean_frames((e_k-b) (e_k-b)^T) )
```

`b` — систематическое смещение; `R` — **центрированная**
ковариация ошибки после предполагаемого вычитания `b`.
Подмена нецентрированного второго момента
`E[e e^T]` ковариацией запрещена: при ненулевом смещении
они математически различны.

На отложенных полетах без повторной подстройки `b,R`:

```text
r_k = e_k - b
NEES_k = r_k^T R^{-1} r_k
```

Отдельно вычисляют среднюю NEES, долю ошибок в
95-процентной области хи-квадрат (две степени свободы),
RMSE после поправки и долю геометрически принятых,
но ложных привязок по **заранее заданному** пределу
ошибки. Выборка должна включать несколько независимых
полетов; многократные видеокадры одного полета сильно
коррелированы.

Вырожденную матрицу `R` программа отвергает, не
вставляя произвольную минимальную дисперсию. Если
наблюдаемая погрешность зависит от высоты, текстуры
местности, освещения, точки на карте или температуры,
одна постоянная матрица на все режимы неприменима.

Пример манифеста (синтаксис, без действительных данных):

```csv
flight_id,partition,candidate_csv,truth_csv
F01,train,F01_candidates.csv,F01_truth.csv
F02,train,F02_candidates.csv,F02_truth.csv
F03,train,F03_candidates.csv,F03_truth.csv
F04,holdout,F04_candidates.csv,F04_truth.csv
F05,holdout,F05_candidates.csv,F05_truth.csv
```

```bash
python -m src.run_map_error_calibration \
  --manifest data/map_calibration_flights.csv \
  --output-dir outputs/map_calibration \
  --false-fix-error-threshold-m 3.0
```

Выход `map_error_calibration.json` содержит смещение,
ковариацию, состав обучающих и независимых проверочных
полетов, статистику каждой проверки и метку
`EMPIRICAL_HOLDOUT_UNCERTIFIED`. Число 3 м в примере
не является требованием или подтвержденной характеристикой НИИВК.

**Недостаточно** получить хорошую NEES по синтетическим
данным: требуется эмпирически подтвердить величину и
режимную зависимость ошибок, независимость эталона,
непредвзятость отбора полетов и влияние редких
ошибочных картографических совпадений.

## 2. Проблема взаимной корреляции с визуальной одометрией

Предсказанная позиция визуально-инерциального РФК
может вычисляться по тем же кадрам, которые используются
для картографической привязки. Тогда ошибки измерений
**не являются независимыми**. Нельзя без проверки
подставлять `S=P+R` в обычную коррекцию Калмана:
это может неоправданно уменьшить дисперсии состояния.

Исследовательский модуль
`src/map_covariance_intersection.py` использует
**ковариационное пересечение** (CI) для двух отдельных
оценок положения в N/E:

```text
P_CI^{-1} = w P_prior^{-1} + (1-w) R_map^{-1}
x_CI = P_CI [w P_prior^{-1} x_prior
            +(1-w) R_map^{-1} x_map]
0 <= w <= 1
```

Вес `w` выбирается минимизацией `log(det(P_CI))`
по конечной сетке с включенными границами. Результат
не претендует на глобальный статистический оптимум,
но воспроизводим и консервативен при корректно заданных
входных ковариациях.

Важно:
- CI не требует знания взаимной корреляции, **но требует
  состоятельности обеих маргинальных ковариаций**
- CI не решает проблему ложной глобальной привязки,
  неправильного датума или временны́х меток
- `x_map` при известном систематическом смещении
  должен пройти отдельную проверенную коррекцию `x_map-b`
- простое изменение двухмерной позиции и подматрицы
  15-мерного ESKF нарушило бы его перекрестные ковариации;
  полноценной схемы обновления ESKF здесь **нет**
- выход всегда `OFFLINE_CI_CANDIDATE_NOT_APPLIED`,
  а `applied_to_eskf=False`

Дополнительные жесткие условия проверки: достоверная
картографическая привязка по критериям целостности,
согласованность СК и часов, подтвержденные
маргинальные ошибки и отсутствие необъяснимого
скачка положения.

## 3. Обязательная экспериментальная проверка НИИВК

Испытательная группа предоставляет минимум раздельные
пакеты записей для настройки и проверки: ортофотоплан
с паспортом геопривязки, калибровку камеры, сырые кадры
и временные метки, независимую эталонную траекторию
в той же СК и сведения о рельефе/условиях освещения.

Необходимо оценить отдельно высоты 20, 50, 100 м,
тип поверхности, время суток, частичные изменения карты,
потери кадра, повторяющиеся структуры и сильные наклоны.
Критерии безопасности должны учитывать в первую очередь
**редкие ложные принятые привязки**, а не только среднюю
погрешность.

После такой проверки возможен следующий этап:
разработка строгой схемы обновления исторического
15-мерного ESKF с сохранением полной ковариации
и контролем целостности, затем стендовые испытания
на целевой бортовой ЭВМ. До этого результат
запрещено выдавать в канал управления БВС.
