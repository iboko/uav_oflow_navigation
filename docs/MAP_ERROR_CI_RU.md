# Оценка погрешностей картографической привязки и ковариационное пересечение

**Статус:** исследовательский офлайн-этап после PR #12. Не является
завершенной VIO, не подключается в PX4 и не выдает разрешений на
управление БВС.

## 1. Раздельная оценка на независимых полетах

Входные данные — кандидат положения по ортофотоплану и независимый
эталон координат в **одной метрической СК N/E и в одинаковый момент
времени**. `run_map_error_calibration.py` принимает два
непересекающихся множества полетов:

- `train` — только для оценки смещения и ковариации
- `holdout` — только для проверки модели после настройки

Обозначим ошибку `e_k = p_map,k - p_ref,k`. По обучающим
полетам с равным весом каждого полета вычисляются:

```text
b = mean_flight( mean_frames(e_k) )
R = mean_flight( mean_frames((e_k-b) (e_k-b)^T) )
```

`b` — систематическое смещение; `R` — **центрированная**
ковариация ошибки после предполагаемого вычитания `b`.
Подмена нецентрированного второго момента
`E[e e^T]` ковариацией запрещена: при ненулевом смещении
они математически различны.

На отложенных полетах без повторной подстройки `b,R`:

```text
r_k = e_k - b
NEES_k = r_k^T R^{-1} r_k
```

Отдельно вычисляют среднюю NEES, долю ошибок в
95-процентной области хи-квадрат (две степени свободы),
RMSE после поправки и долю геометрически принятых,
но ложных привязок по **заранее заданному** пределу
ошибки. Выборка должна включать несколько независимых
полетов; многократные видеокадры одного полета сильно
коррелированы.

Вырожденную матрицу `R` программа отвергает, не
вставляя произвольную минимальную дисперсию. Если
наблюдаемая погрешность зависит от высоты, текстуры
местности, освещения, точки на карте или температуры,
одна постоянная матрица на все режимы неприменима.

Пример манифеста (синтаксис, без действительных данных):

```csv
flight_id,partition,candidate_csv,truth_csv
F01,train,F01_candidates.csv,F01_truth.csv
F02,train,F02_candidates.csv,F02_truth.csv
F03,train,F03_candidates.csv,F03_truth.csv
F04,holdout,F04_candidates.csv,F04_truth.csv
F05,holdout,F05_candidates.csv,F05_truth.csv
```

```bash
python -m src.run_map_error_calibration \
  --manifest data/map_calibration_flights.csv \
  --output-dir outputs/map_calibration \
  --false-fix-error-threshold-m 3.0
```

Выход `map_error_calibration.json` содержит смещение,
ковариацию, состав обучающих и независимых проверочных
полетов, статистику каждой проверки и метку
`EMPIRICAL_HOLDOUT_UNCERTIFIED`. Число 3 м в примере
не является требованием или подтвержденной характеристикой НИИВК.

**Недостаточно** получить хорошую NEES по синтетическим
данным: требуется эмпирически подтвердить величину и
режимную зависимость ошибок, независимость эталона,
непредвзятость отбора полетов и влияние редких
ошибочных картографических совпадений.

## 2. Проблема взаимной корреляции с визуальной одометрией

Предсказанная позиция визуально-инерциального РФК
может вычисляться по тем же кадрам, которые используются
для картографической привязки. Тогда ошибки измерений
**не являются независимыми**. Нельзя без проверки
подставлять `S=P+R` в обычную коррекцию Калмана:
это может неоправданно уменьшить дисперсии состояния.

Исследовательский модуль
`src/map_covariance_intersection.py` использует
**ковариационное пересечение** (CI) для двух отдельных
оценок положения в N/E:

```text
P_CI^{-1} = w P_prior^{-1} + (1-w) R_map^{-1}
x_CI = P_CI [w P_prior^{-1} x_prior
            +(1-w) R_map^{-1} x_map]
0 <= w <= 1
```

Вес `w` выбирается минимизацией `log(det(P_CI))`
по конечной сетке с включенными границами. Результат
не претендует на глобальный статистический оптимум,
но воспроизводим и консервативен при корректно заданных
входных ковариациях.

Важно:
- CI не требует знания взаимной корреляции, **но требует
  состоятельности обеих маргинальных ковариаций**
- CI не решает проблему ложной глобальной привязки,
  неправильного датума или временны́х меток
- `x_map` при известном систематическом смещении
  должен пройти отдельную проверенную коррекцию `x_map-b`
- простое изменение двухмерной позиции и подматрицы
  15-мерного ESKF нарушило бы его перекрестные ковариации;
  полноценной схемы обновления ESKF здесь **нет**
- выход всегда `OFFLINE_CI_CANDIDATE_NOT_APPLIED`,
  а `applied_to_eskf=False`

Дополнительные жесткие условия проверки: достоверная
картографическая привязка по критериям целостности,
согласованность СК и часов, подтвержденные
маргинальные ошибки и отсутствие необъяснимого
скачка положения.

## 3. Воспроизводимая офлайн-проверка кандидата объединения

`src/run_map_ci_offline.py` принимает CSV с предварительными
двухмерными координатами и маргинальной ковариацией РФК:

```csv
timestamp_us,prior_n_m,prior_e_m,prior_cov_nn_m2,prior_cov_ne_m2,prior_cov_ee_m2
1000000,10.0,-2.0,1.0,0.0,1.0
```

Дополнительно требуются `orthophoto_candidates.csv`
из PR #12 с полем `temporal_integrity_status`,
файл `map_error_calibration.json` от этапа настройки
и подтверждения испытательной группы в YAML:

```yaml
prior_covariance_independently_validated: false
map_covariance_independently_validated: false
reference_frames_and_timestamps_aligned: false
independent_map_integrity_review: false
max_position_disagreement_m: 20.0
```

Эти признаки **по умолчанию false**. Выставлять их
в true без измерений, подтверждений СК, статистики
ложных привязок и проверки погрешностей запрещается.
Программа проверяет, что временные метки двух журналов
совпадают строго, вычитает обученное смещение `b`
из картографической координаты и формирует
`map_ci_candidates.csv` только для дальнейшего
математического анализа. Выход `applied_to_eskf=0`
фиксирован, даже если все призна́ки объявлены true.

```bash
python -m src.run_map_ci_offline \
  --prior-csv data/prior_ne.csv \
  --map-candidates-csv outputs/map_localization/orthophoto_candidates.csv \
  --calibration-json outputs/map_calibration/map_error_calibration.json \
  --verification-yaml data/ci_review.yaml \
  --output-dir outputs/map_ci
```

`map_ci_summary.json` дополнительно фиксирует,
что признаки подтверждения — **декларации испытательной
группы**, а не автоматически проверенный допуск.
Двухмерная ковариация CI не заменяет матрицу полного
15-мерного РФК и не дает права напрямую передать
результат в PX4.

## 4. Программа разработки без записей НИИВК

По условиям проекта **синхронизированные видеозаписи, журналы
ИИМ и независимые эталонные полетные данные НИИВК недоступны и
не ожидаются**. Их получение исключено из критериев завершения
этого исследовательского этапа. Недопустимо подменять их
«реалистичными» синтетическими файлами без явной маркировки.

Вместо этого создан `src/synthetic_map_campaign.py`.
Он **не моделирует оптику и физику БВС полностью**: это
воспроизводимая статистическая модель координат в N/E
с аналитической опорной траекторией. Четыре режима:

- `nominal`: смещение карты, цветной шум ошибки
  и относительный дрейф инерциального прогноза
- `shared_correlation`: дополнительная **общая**
  ошибка карты и визуально-инерциального прогноза
- `false_match_burst`: несколько последовательных
  ошибочных картографических привязок, которые могут
  пройти геометрическую проверку
- `camera_outage`: продолжительная недоступность
  картографических измерений

Генератор задает seed, количество модельных независимых
полетов и отсчетов, отдельно формирует тренировочные
и проверочные серии. В его отчете разделены RMSE
исходного прогноза, карты после коррекции систематического
смещения и кандидата ковариационного пересечения.
Указаны недоступные кадры, число заданных ложных
привязок, число отказов по расхождению координат,
а также случаи ошибки после объединения.

```bash
python -m src.synthetic_map_campaign \
  --output-dir outputs/synthetic_map \
  --seed 14921 \
  --frames-per-flight 120
```

Получаются `synthetic_map_campaign.json` и
`synthetic_map_scenarios.csv`. Во всех файлах
фиксируется `SYNTHETIC_STATISTICAL_SURROGATE_ONLY`.
Рассчитанные параметры ошибок **не разрешено**
использовать как подтвержденные характеристики
реального оборудования.

Принятый критерий завершения этого этапа —
наличие воспроизводимых алгоритмов и CI-тестов
на синтетических входах, явная обработка отказов,
корректное разделение обучающих и проверочных
сценариев, отсутствие ложного уменьшения
ковариации при полной корреляции двух оценок и
невозможность внесения непроверенной поправки в ESKF.

Для развития до реальной бортовой навигации нужны
отдельные испытания на физическом оборудовании,
метрологическая калибровка, измерение задержек,
контроль вычислительных ресурсов и оценка точности
по независимому эталону. Они **не могут считаться
выполненными** за счет программной симуляции.
