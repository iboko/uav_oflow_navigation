# C++17: 15-мерный РФК и история запаздывающих визуальных измерений

**Назначение:** математический исследовательский перенос Python-модели
`src/error_state_inertial_filter.py` и
`src/fixed_lag_eskf_replay.py` на C++17 с заранее ограниченным
объемом памяти. Синхронизированные записи НИИВК не требуются.

**Степень готовности:** автономная C++ библиотека + регрессионные
тесты. Код **компилируется в PX4 SITL для контроля совместимости**,
но не создается и не выполняется в штатном `ofnav`-модуле PX4.
Нет публикации состояния в `vehicle_odometry`, `EKF2`,
управление БВС или интерфейс исполнительных органов.

## Модель и системы координат

Навигационная система NED (север–восток–вниз).
Связанная система БВС FRD (вперед–вправо–вниз).
Гравитация `g_NED = [0, 0, +9.80665]` м/с².
Акселерометр измеряет **удельную силу**, поэтому
неподвижный горизонтальный ИИМ сообщает примерно
`[0, 0, -9.80665]`, а не нулевое ускорение.

Номинальное состояние состоит из `p_NED(3)`,
`v_NED(3)`, кватерниона `q_FRD_to_NED(4)`,
смещений гироскопов `bg(3)` и акселерометров
`ba(3)`. Ошибка состояния в установленном порядке:

```text
delta_x = [delta_p_NED(3), delta_v_NED(3),
           delta_theta_body(3), delta_bg_body(3),
           delta_ba_body(3)]
```

Поворот правый: `R_true = R_nom Exp([delta_theta]x)`.
Прогноз по двум смежным отсчетам ИИМ использует
средние `omega, specific_force`, ориентацию
на середине интервала, инерциальную силу с
возвратом гравитации и кинематическое интегрирование
`p,v,q`. Временная разница должна быть
`0 < dt <= 0.05` с в текущей конфигурации.

Матрица перехода `Phi` вычисляется через
степенной ряд `exp(F dt)` до четвертого порядка.
Матрица процессного шума получается из
`integral Phi(t) G Qc G^T Phi(t)^T dt`
трехточечной гауссовой квадратурой. Шумы
гироскопов, акселерометров и случайного
блуждания их смещений нуля заданы явно.
**Численная схема не является точным аналитическим
решением при любом шаге/движении.**

## Обновление визуальной скорости

Визуальное измерение содержит `VN,VE`, время
измерения и положительно определенную матрицу
дисперсий `R(2x2)`. Модель `h(x)=[VN,VE]`.
Матрица `H` выбирает компоненты скорости
с индексами 3 и 4 в `delta_x`.

Проверяются инновация, 2-мерная
нормированная квадратичная инновация (NIS),
численная обусловленность матрицы `S`
и порог отклонения выбросов. Для принятого
измерения:

```text
K = P H^T S^-1
Pplus = (I-KH) P (I-KH)^T + K R K^T
Greset_theta = I - 0.5 [delta_theta]x
P_reset = Greset Pplus Greset^T
```

Коррекция используется для всех 15 ошибок,
а не только двух компонент скорости. Проверяются
полная симметрия, положительная определенность
и пределы смещений нуля. Кватернион нормируется.

**Не утверждается наблюдаемость всех 15 компонент**
от одних двух компонент визуальной скорости;
для полной наблюдаемости нужны дополнительные
измерения/возбуждения и анализ.

## История: ограничение памяти и повторный расчет

Класс `FixedLag` содержит текущий фильтр,
контрольное состояние на левой границе окна,
до **64** сохраненных отсчетов ИИМ и **12**
визуальных измерений. События ИИМ поступают
строго по возрастающим меткам. Поздние
визуальные измерения допускаются в пределах
настроенного окна `max_lag_us`.

Для позднего кадра вычисление проводится
на копии контрольного состояния:
выполняется повторный прогноз до кадра,
при необходимости **линейная интерполяция ИИМ**
на время экспозиции, коррекция скорости,
затем повторный прогноз по оставшимся ИИМ
и другим ранее принятым визуальным измерениям.
Новый результат записывается **только после
успешного завершения полного пересчета**.
Неверный/повторный/слишком старый кадр
не меняет ранее рассчитанное состояние.
При достижении предела хранения возвращается
`BUFFER_LIMIT`, без выделения новой памяти.

Контрольное состояние обновляется при
выходе архивных отсчетов за допустимое
временное окно. Обработка интерполированных
событий и расчет ковариации остаются
вычислительно затратными; **наихудшее время
исполнения, максимальная глубина стека и
пригодность для целевого процессора не
установлены**. Нельзя запускать этот
алгоритм в имеющемся потоке PX4 со стеком
4 КиБ без отдельного анализа памяти.

## Испытания без НИИВК

Тест `firmware/rtos_core/tests/test_eskf15.cpp`
проверяет аналитические случаи: неподвижность
и знак гравитации, равноускоренное движение,
поворот по курсу, симметрию/положительную
определенность ковариации 15×15, коррекцию
визуальной скорости, отклонение выбросов,
недопустимые смещения по времени ИИМ,
сохранение состояния при ошибочном позднем
измерении, одинаковый результат при
перестановке порядка получения поздних
кадров и ограничение буфера.

```bash
cmake -S firmware/rtos_core -B build/rtos_core \
  -DOFNAV_BUILD_TESTS=ON
cmake --build build/rtos_core --parallel
ctest --test-dir build/rtos_core --output-on-failure
```

CI также собирает PX4 v1.16.2 SITL,
чтобы обнаруживать несовместимости
C++ исходников с его конфигурацией.

## Контроль математической эквивалентности C++ и Python

Добавлена отдельная проверка
`src/compare_cpp15_python.py` и
детерминированный автономный двоичный эталон
`eskf15_parity`.

Оба фильтра получают идентичные 50 отсчетов ИИМ,
причем два визуальных измерения поступают в обратном
порядке относительно времени экспозиции. Одно
визуальное измерение находится **между двумя
метками ИИМ**, что проверяет интерполяцию.
Принимаемая метрика — максимальная абсолютная
разница отдельно для `p(3)`, `v(3)`,
`q(4)`, `bg(3)`, `ba(3)`, **каждого
из 225 элементов матрицы ковариации** и NIS.

```bash
cmake -S firmware/rtos_core -B build/rtos_core
cmake --build build/rtos_core --parallel
python -m src.compare_cpp15_python \
  --cpp-executable build/rtos_core/eskf15_parity \
  --output build/eskf15_parity/cpp_python_full_covariance.json
```

В CI результат сохраняется в
`cpp15-python-full-covariance-parity`.
Проверка эквивалентности **одного синтетического
сценария** не является доказательством верности
линеаризации на всех режимах или соответствия
реальному датчику.

## Что остается для реального замкнутого SITL

- Повторение C++/Python сравнений на **нескольких**
  различных траекториях, со смещениями ИИМ и
  высокими угловыми скоростями, а не только
  на одной синтетической последовательности.
- Ограничение максимальной сложности и
  измерение наихудшего времени пересчета
  на целевой конфигурации.
- Отдельный процесс/модуль диагностики
  с безопасной передачей временных
  меток; **не подмена входа EKF2**.
- Динамический PX4 SITL со штатным
  симулятором движения, а не только
  встроенный read-only replay из PR #15.
- Отдельная проверка моделей реальных
  камер, высотомеров, ИИМ и геопривязки.
  Синтетика не подтверждает точность
  реального БВС на высоте 100 м.
