# VO на компаньон-компьютере → EKF2: потеря ГНСС в полете (PX4 SITL + Gazebo)

## Что было

Визуальная одометрия по нижней камере (`ContinuousPlanarOdometry`)
работала только офлайн, по записанным кадрам и журналу ориентации.
Бортового конвейера не было: ни приема кадров в реальном времени, ни
согласования часов камеры и автопилота, ни передачи результата в EKF2.

## Архитектура

```
камера ──кадры (часы компаньона)──┐
                                  ▼
PX4 ──MAVLink ATTITUDE_QUATERNION, DISTANCE_SENSOR (часы PX4)──► компаньон:
     ◄──────────── TIMESYNC в обе стороны ────────────────────►  src/companion_vo.py
     ◄──── ODOMETRY: скорость FRD + дисперсии (часы компаньона) ─┘
EKF2 (EKF2_EV_CTRL=4): слияние 3D-скорости
```

- `src/companion_vo.py` — логика без ввода-вывода (покрыта тестами):
  - `TimeOffset` — смещение часов по обмену TIMESYNC, берется отсчет с
    минимальной задержкой круга, круг > 50 мс отбрасывается;
  - `History` — отсчеты автопилота, интерполяция без экстраполяции и
    с ограничением разрыва;
  - `CompanionVo` — ориентация и высота на середину экспозиции, VO,
    вертикальная скорость по дальномеру на интервале той же пары
    кадров, поворот в оси корпуса FRD вместе с ковариацией.
- `tools/gz_vo_companion.py` — отдельный процесс-компаньон: кадры
  Gazebo (gz-transport), MAVLink к PX4 (`udpin:14540`, канал onboard).
  Часы компаньона — время симуляции. Узел отвечает на запросы TIMESYNC
  от PX4 (PX4 переводит метку ODOMETRY в свое время) и шлет свои (для
  перевода меток ориентации и дальности во время камеры).

Правила, как в `ofnav`:

- вертикальная скорость — измеренная (изменение высоты по дальномеру
  на интервале пары), а не подставленная. Без высоты по обе стороны
  интервала измерение не выдается;
- ниже 0,5 м измерение не выдается: пятно на земле — несколько
  сантиметров, изображение размыто на взлете и посадке;
- измерение старше 200 мс к моменту отправки отбрасывается. Если
  синхронизация PX4 еще не сошлась, PX4 ставит метку прихода, и
  запоздавшее измерение было бы слито как текущее;
- положение и ориентация в ODOMETRY — NaN: передается только скорость.

## Сценарий

`tools/gz_vo_companion_flight.py`:

- аппарат `x500_vo_down` (ставится сценарием): x500 с ГНСС, нижняя
  камера 320×240, 69°, 15 Гц, нижний лидар (тот же, что в `x500_flow`).
  Мир — `ofnav_textured`;
- предполетная проверка: EKF2 сливает ГНСС и 5 с неподвижен. Под
  нагрузкой старт SITL иногда оставляет EKF2 без коррекции ~30 с
  (уход в сотни метров), и проверки армирования уже проходят, пока
  оценка еще сходится. Такой прогон без этой проверки «взлетал» на
  1,5 м вместо 3 м;
- **потеря ГНСС**: в Gazebo нет инъекции отказа ГНСС (`failure gps`
  поддерживает только симулятор MAVLink), поэтому потеря задается в
  оценивателе: `EKF2_GPS_CTRL=0` в полете. Для EKF2 это равносильно
  пропаже приемника, но приемник при этом продолжает выдавать данные;
- эталон — `vehicle_local_position_groundtruth` (Gazebo).

## Результат

| № | Проверка | Результат |
|---|---|---|
| 1 | с ГНСС: EKF2 сливает ГНСС и VO; VO против эталона (зависание, движение до 0,7 м/с) | PASS: `cs_ev_vel=True`, `cs_gnss_pos=True`; СКО скорости VO 0,026 м/с, смещение (−0,002; 0,002) м/с |
| 2 | потеря ГНСС в полете | PASS: `cs_gnss_pos=False`, `cs_ev_vel=True`, `xy_valid=True` |
| 3 | POSCTL, 60 с | PASS: истинный уход 0,02 м, ошибка оценки 0,03 м |
| 4 | ручка вперед 30 % на 5 с (0,8 м/с), отпускание | PASS: 2,89 м (истинное) / 2,94 м (оценка), уход после остановки 0,02 м |
| 5 | AUTO.LAND на VO | PASS: посадка, разоружение |

Компаньон за полет: 2194 измерения передано; 193 кадра ниже 0,5 м;
10 — без ориентации или дальности; потерь трекинга в воздухе нет.
Смещение часов, оцененное PX4, — 0,6 мс (в SITL часы PX4 совпадают со
временем симуляции, смещение компаньона — 0).

Модельная СКО горизонтальной скорости (0,11 м/с) в 4 раза больше
фактической (0,026 м/с). В симуляции нет шумов изображения и
вибраций: подтверждать модель ковариации по ней нельзя (см.
`docs/VO_COVARIANCE_CALIBRATION_RU.md`).

### Найдено при отладке

- PX4 при запуске принимает за работающий мир Gazebo любую тему
  `/world/*/clock`, даже одну подписку компаньона. Поэтому компаньон
  запускается после первого heartbeat PX4;
- узел должен за каждый проход вычитывать все сообщения MAVLink.
  Иначе ответы TIMESYNC запаздывают, и синхронизация не сходится
  («RTT too high»);
- прогон с несошедшейся оценкой EKF2 на земле разобран по журналу
  ulog: уход до первого измерения VO, VO в нем не участвовал.

## Ограничения

- Только моделирование: идеальная камера (без шумов, смаза, рольставня
  и экспозиции), текстурированная плоская сцена 20×20 м, нет ветра.
  Метка кадра Gazebo — точное время экспозиции; на реальной камере его
  надо получать аппаратно (см. сдвиг −37 мс в `docs/REAL_DATA_MUNFRL_RU.md`).
- Потеря ГНСС задается в EKF2, а не отказом приемника.
- Курс — из EKF2 (магнитометр симулятора). Курсовой дрейф без ГНСС не
  проверяется: полет короткий.
- Высота ограничена дальномером и текстурой: проверено на 3 м. Профиль
  `camera` (5–120 м) в этом сценарии не проверялся.
- Это не VIO: VO дает скорость по паре кадров, инерциальное слияние
  выполняет EKF2 автопилота.

## Воспроизведение

```sh
make -C PX4-Autopilot px4_sitl_default    # gz Harmonic
# Python с gz.transport13 / gz.msgs10 (системный 3.12 в Ubuntu 24.04):
python3.12 -m venv --system-site-packages venv312
venv312/bin/pip install numpy opencv-python-headless pymavlink pillow
cd tools && ../venv312/bin/python gz_vo_companion_flight.py ../PX4-Autopilot --out ../build/gz_vo_companion
cat ../build/gz_vo_companion/gz_vo_companion_flight.json
```
