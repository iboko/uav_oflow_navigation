# Проверка статистической согласованности и наблюдаемости РФК БВС

**Назначение:** независимая численная проверка 15-мерного фильтра
ошибок состояния, используемого в задачах навигации БВС без ГНСС.
Это исследовательская процедура для исходных данных НИИВК;
результат не является заключением о летной годности.

## Состав проверки

**1. Ошибка горизонтальной скорости (NEES с двумя степенями свободы).**
При совпадении временных меток РФК и независимого эталона в одной СК NED:

```text
e_v = [VN_РФК - VN_эталон, VE_РФК - VE_эталон]^T
P_v = P[3:5, 3:5]  # полная подматрица, включая корреляцию N/E
NEES_2 = e_v^T P_v^(-1) e_v
```

Здесь используется маргинальная ковариация скорости, а не
обратная матрица всей ковариации 15×15. Перед вычислением
проверяется положительная определенность `P_v`. При идеальной
гауссовой согласованности математическое ожидание NEES_2 равно 2.
Для отдельного независимого измерения порог 95 %:
`χ²(2;0.95)=5,99146`. На последовательности автокоррелированных
кадров прямое применение биномиальных доверительных интервалов
без учета корреляции некорректно.

**2. Полный NEES (15 степеней свободы).** Возможен только при наличии
независимых эталонных трехмерного положения, трехмерной скорости,
ориентации и смещений нуля ИИМ, а также документированной
привязки начала координат и курса. Ошибка ориентации
вычисляется как логарифм правой ошибки вращения:

```text
δθ = Log(R_nominal^T R_reference)
e_15 = [p_ref-p_est, v_ref-v_est, δθ, bg_ref-bg_est, ba_ref-ba_est]
NEES_15 = e_15^T P_15^(-1) e_15
```

Без этих условий программа **не подставляет нули вместо неизвестного
эталона** и не выдает полный NEES. Для зависания без привязки
абсолютные координаты и курс могут оставаться ненаблюдаемыми.
Булевы признаки подтверждения привязки в файлах — заявление
испытательной группы, не автоматическое доказательство
корректности данных.

**3. Нормированная инновация (NIS).** Используется журнал
`delayed_visual_replay.csv` из предыдущего PR. При
сравнении учитываются **все** вычисленные инновации, включая
отклоненные порогом, но не вычисляется NIS для невалидных
измерений. Применяется проверочный порог 9,21034
для двух компонент визуальной скорости (99-й процентиль
хи-квадрат распределения). Нельзя делать вывод о статистической
согласованности по среднему NIS **только принятых** измерений.

**4. Наблюдаемость.** На выбранной траектории строится
локальная линеаризация непрерывной инерциальной модели
`F(t)`, соответствующие матрицы перехода `Φ(t_k,t_0)`
и строки `H_k Φ(t_k,t_0)`, где `H_k` выделяет скорость
по осям N/E. Численный ранг вычисляется по сингулярным
числам с фиксируемым относительным порогом.

Это **локальный** тест выбранного движения и модели, а не
доказательство глобальной нелинейной наблюдаемости.
Первые три столбца матрицы наблюдаемости при измерении
только скорости равны нулю: глобальное перемещение
начала координат невозможно определить без дополнительных
опорных измерений.

## Подготовка исходных данных

Первый шаг — выполнить ранее реализованный офлайн-обработчик
15-мерного РФК, который дополнительно сохраняет
`eskf_states.jsonl`. Каждая строка содержит
`timestamp_us`, положение, скорость, кватернион,
смещения нуля ИИМ и **полную ковариацию 15×15**.
Все данные относятся к моменту состояния; если
ИММ/кадр не согласованы, ложный снимок не создается.

Отдельный `truth.csv` должен содержать:

```csv
timestamp_us,vn_m_s,ve_m_s,vd_m_s,source
1005000,0.01,0.00,0.00,independent-motion-capture
1105000,0.03,0.01,0.00,independent-motion-capture
```

`source` указывает **независимую** измерительную систему.
Запрещено использовать саму оценку РФК в качестве эталона.
Одна только текстовая метка источника не гарантирует его
фактическую независимость. Эталон должен быть согласован
по времени с ИИМ и приведен к той же навигационной СК NED.

Для анализа полного NEES эталон дополнительно содержит
`north_m,east_m,down_m,qw,qx,qy,qz`,
`bg_x_rad_s,bg_y_rad_s,bg_z_rad_s` и
`ba_x_m_s2,ba_y_m_s2,ba_z_m_s2`.

Перечень **независимых полетов** `validation/flights.csv`:

```csv
flight_id,states_jsonl,truth_csv,nis_csv,linearization_csv,origin_alignment_verified,heading_alignment_verified
F01,data/F01_states.jsonl,data/F01_truth.csv,data/F01_nis.csv,data/F01_linear.csv,0,0
F02,data/F02_states.jsonl,data/F02_truth.csv,,,0,0
```

Пути относительны каталогу перечня. Пропуски
`nis_csv` и `linearization_csv` допустимы;
программа честно помечает эти проверки как непримененные.

Для численного анализа наблюдаемости
`linearization_csv` содержит по строке на временной
интервал колонки:

```text
dt_s,qw,qx,qy,qz,wx_rad_s,wy_rad_s,wz_rad_s,fx_m_s2,fy_m_s2,fz_m_s2
```

`q` переводит FRD в NED, `ω` и `f` — в осях
корпуса, `dt_s` не превышает 0,05 с.

## Выполнение

```bash
python -m pip install -e '.[dev,vision]'
python -m src.run_eskf_consistency \
  --manifest validation/flights.csv \
  --output-dir outputs/consistency
```

Файлы результатов:
- `eskf_reference_errors.csv` — ошибки и NEES в согласованные моменты
- `eskf_consistency_summary.json` — по полетам ошибки, охват
  временных меток, оценка NIS/наблюдаемости, среднее NEES
  **с одинаковым весом каждого полета**, предварительный
  бутстреп по полетам, а не по отдельным кадрам

Даже если имеются три полета и более 30 точных совпадений
на каждый, это только формальная достаточность для
первичного анализа. Она не означает, что испытания
подтвердили модель ошибок или точность БВС. Для выводов
нужны результаты на **не участвовавших в настройке**
полетах, проверка случайных/систематических составляющих,
автокорреляции, доверительных интервалов и воспроизводимости.

## Требования к испытаниям НИИВК

Следует предоставить независимый эталон координат,
скорости и ориентации, протоколы метрологической
калибровки, временны́е метки камеры/ИИМ, сведения о
высоте над подстилающей поверхностью, особенностях
ландшафта и освещения. Проводить отдельные испытания
на высотах 20, 50, 100 м с различными маневрами,
длительным зависанием и искусственными пропусками кадров.

**Пока реальные данные не представлены, все численные
примеры в автотестах — синтетические и не доказывают
возможность удержания позиции БВС без ГНСС.**
