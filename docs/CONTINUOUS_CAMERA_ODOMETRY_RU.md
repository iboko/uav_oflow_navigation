# Непрерывная визуальная одометрия БВС по нижней камере

**Состояние разработки:** программно-математический офлайн-прототип (этап 4).
Не является готовой системой VIO, удержания точки на 100 м или альтернативой
достоверной абсолютной навигации. Для полета канал управления не подключен.

## Реализация и границы применимости

`src/ground_visual_motion.py` по паре кадров определяет относительную скорость
камеры при плоской статичной поверхности. `src/continuous_visual_odometry.py`
выполняет последовательное накопление горизонтального перемещения относительно
первого кадра каждого непрерывно наблюдаемого участка, используя крен/тангаж
для проверок и курс для перехода в навигационную систему координат.

Алгоритм контролирует:
- монотонность временных меток **середины экспозиции**, максимальный интервал;
- достаточность и пространственную разнесенность характерных точек;
- согласованность прямого/обратного сопровождения и выбросы RANSAC;
- расхождения высоты и курса, границы малых крена/тангажа;
- изменение крена/тангажа между кадрами: без трехмерной калибровки установки
  камеры и угловой компенсации этот эффект нельзя отличить от переноса;
- потерю текстуры или ошибочные исходные кадры.

**При любом обрыве** начинается новый независимый `segment_id`, отсчет
координат заново равен нулю. Соседние участки не сшиваются искусственно:
сдвиг за ненаблюдаемый промежуток неизвестен. `resolution_proxy_m` —
только индикатор влияния конечного разрешения пикселей, **не ковариация**,
не доверительный интервал и не граница гарантированной погрешности.

Для длительного зависания на 100 м необходимо внешнее устранение дрейфа по
ортофотоплану либо опорным ориентирам. Эти алгоритмы еще не реализованы.

## Компенсация вращения камеры по калиброванной ориентации

Добавлен модуль `src/camera_rotation_compensation.py`. При наличии
проверенной трехмерной матрицы `body_from_camera` вычисляется гомография
чистого вращения камеры между кадрами. Текущий кадр приводится к ориентации
предыдущего, затем на выровненной паре выполняется оценка поступательного
движения по характерным точкам. Проверяется доля перекрытия изображений.

Приняты системы координат: связанная СК БВС — **FRD** (вперед, вправо,
вниз), навигационная — **NED** (север, восток, вниз); СК камеры:
ось X направлена вправо изображения, ось Y — вниз изображения,
ось Z — по оптической оси.

Для устраненной дисторсии камеры и известной установки:

```text
R_nb = R_z(yaw) R_y(pitch) R_x(roll)
R_c2_c1 = R_bc.T @ R_nb2.T @ R_nb1 @ R_bc
H_prev_to_current = K @ R_c2_c1 @ inv(K)
current_aligned = warpPerspective(current, inv(H_prev_to_current))
```

Здесь `K` — матрица внутренних параметров камеры; `R_bc` — поворот
от камеры к связанной СК БВС. Порядок матриц и оси должны совпадать с
реально измеренной калибровкой; неверная ориентация может создать
фиктивную скорость.

Добавляемый параметр к YAML:

```yaml
# Пример ТОЛЬКО для строго надирной установки, не для любого БВС.
focal_x_px: 900
focal_y_px: 900
center_x_px: 320
center_y_px: 240
image_to_body_xy: [[0, -1], [1, 0]]
body_from_camera: [[0, -1, 0], [1, 0, 0], [0, 0, 1]]
```

Без `body_from_camera` сохраняется прежнее поведение: изменения крена и
тангажа выше установленного порога приводят к отклонению интервала.
При наличии матрицы проверяются ее ортонормированность, правая ориентация
осей, близость камеры к надиру и согласованность с двумерной матрицей.

**Ограничения:** углы берутся на середину экспозиции, а не автоматически
интегрируются из ИИМ; вращение в течение экспозиции, перекос строк
скользящего затвора, временные сдвиги, поступательное смещение между
ИИМ и камерой (плечо установки) и неплоский рельеф здесь не компенсируются.
Преобразование `H` устраняет только угловое движение, поэтому этот
алгоритм не является полноценной визуально-инерциальной одометрией.

## Воспроизводимая обработка видеолога НИИВК

```bash
python -m pip install -e '.[dev,vision]'
python -m src.run_camera_odometry \
  --manifest data/frames.csv \
  --calibration data/camera.yaml \
  --output-dir outputs/camera_vo
```

Пример `data/camera.yaml` (ОСИ УСЛОВНЫЕ, НЕ ДЛЯ БОРТОВОГО ПРИМЕНЕНИЯ):

```yaml
focal_x_px: 1400
focal_y_px: 1400
center_x_px: 320
center_y_px: 240
image_to_body_xy: [[1, 0], [0, 1]]
```

Реальные `fx, fy, cx, cy`, дисторсия камеры и матрица преобразования осей
должны быть измерены и проверены на стенде НИИВК. Перед использованием кадров
необходимо устранить дисторсию при подготовке входных изображений.
Все кадры должны иметь одно разрешение, единые настройки камеры и общую
шкалу времени с ИИМ/высотомером.

Файл `data/frames.csv` в заданном порядке строк:

```csv
timestamp_us,image_path,height_agl_m,roll_rad,pitch_rad,yaw_rad
1000000,frames/0001.png,100.0,0,0,0
1100000,frames/0002.png,100.0,0,0,0
1200000,frames/0003.png,100.0,0,0,0
```

При наличии независимого эталона можно добавить **оба** столбца
`true_n_m,true_e_m` (положение в навигационной СК в метрах). Эталон используется
**только после оценивания** для расчета относительной ошибки внутри участков;
ни один из эталонных столбцов в алгоритм оценки движения не подается.

Результаты:
- `visual_odometry.csv`: временные метки, индекс участка, причины отказов,
  скорость/смещение, количество и доля согласованных точек;
- `visual_odometry_summary.json`: доля принятых интервалов, количество
  независимых участков, распределение отказов, условные RMSE и 95-й процентиль
  ошибки *относительных* координат при наличии эталона.
