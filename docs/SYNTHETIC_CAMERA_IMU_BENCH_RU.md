# Сквозной синтетический стенд камеры, ИИМ и навигации БВС без ГНСС

**Назначение:** воспроизводимая проверка алгоритмов при отсутствии синхронизированных записей НИИВК. Реализован автономный программный стенд без аппаратуры и полетных данных. Он запускает **существующие**, а не специально упрощенные, модули визуальной одометрии, привязки к ортофотоплану и отложенного 15-мерного РФК.

## 1. Модель сцены и движения

Единственный статический растр `synthetic_orthophoto.png` создается из детерминированно размещенных контрастных точек. Его пиксели связаны с локальными координатами **север–восток в метрах** известным аффинным преобразованием. Предполагается плоская горизонтальная поверхность и одна геодезическая система координат.

Для каждого расчетного момента `t` формируется аналитическая траектория:

```text
N(t) = 50 + 1.08 t + 0.20 sin(0.40 t)
E(t) =  6 + 0.30 t + 0.12 sin(0.30 t)
VN(t) = 1.08 + 0.08 cos(0.40 t)
VE(t) = 0.30 + 0.036 cos(0.30 t)
aN(t) = -0.032 sin(0.40 t)
aE(t) = -0.0108 sin(0.30 t)
```

Высота синтетического оптического центра над плоскостью равна 100 м по умолчанию. Поза камеры определяется идеальной внутренней калибровкой `fx,fy,cx,cy` и известной трехмерной установкой камеры относительно FRD корпуса. Ее луч пересекает плоскость в NED:

```text
ray_NED = R_body_to_NED R_body_from_camera K^-1 [u,v,1]^T
ground_NE = camera_NE + height * ray_NE / ray_D
map_uv = affine_map_NE^-1 (ground_NE - map_origin_NE)
```

Для всех пикселей применяется одна гомография к плоской ортофотокарте, а не произвольный программный сдвиг изображения. В сценарии `yaw_rotation` моделируется также аналитическое изменение курса.

Из этой **той же траектории** формируются измерения ИИМ:

```text
omega_body = [0,0,yaw_rate] + simulated_gyro_noise
specific_force_body = R_body_to_NED^T [aN,aE,-g] + simulated_accel_noise
```

Это лишь ограниченная модель идеальных датчиков. Не моделируются вибрации конструкции, температурные дрейфы, реальные смещения нуля, скользящий затвор, рельеф, аэродинамика и характеристики фактического БВС.

## 2. Временные соглашения

ИИМ выдает измерения с расчетной частотой 100 Гц (по умолчанию), камера — 5 Гц. Измерительная метка кадра относится к **середине экспозиции** в общей шкале, метка `arrival_timestamp_imu_us` — к его программному получению позднее. Высота имеет собственную метку `range_timestamp_us`, проверяемую на согласованность с кадром.

Это задаваемые **идеализированные** задержки. Никакой реально измеренной ошибки синхронизации в модель не загружено. При потере кадра запись остается в манифесте, но изображение не подменяется предыдущим.

## 3. Реально используемые алгоритмы проекта

`src/synthetic_sensor_bench.py` вызывает:

- `ContinuousPlanarOdometry` — вычисление относительной горизонтальной визуальной скорости по настоящим сгенерированным PNG-кадрам
- `OrthophotoLocalizer` — ORB/RANSAC-сопоставление с исходной картой, включая проверку неоднозначности
- `FixedLagEskfReplay` + `InertialErrorStateFilter` — интегрирование сырых отсчетов ИИМ и коррекция горизонтальной скорости по **времени экспозиции**, а не получения кадра

Моделирование не заменяет алгоритм локализации доступом к известной траектории. Файл `truth.csv` открывается только **после** вычисления всех оценок, исключительно для расчета ошибок. В поле `applied_map_correction` всегда указан нуль: без независимой калибровки ковариаций и контроля целостности картографическая коррекция не вносится в ESKF.

## 4. Сценарии

| Сценарий | Проверяемая ситуация |
|---|---|
| `nominal` | Передача корректных кадров/ИИМ и задержанная визуальная скорость |
| `yaw_rotation` | Геометрически согласованный поворот камеры, компенсация вращения |
| `camera_blackout` | Пропуск кадров 2 и 3; новый независимый участок визуальной одометрии |
| `imu_gap` | Разрыв отсчетов ИИМ и зафиксированное отказное состояние навигации |
| `duplicate_map` | Два одинаковых изображения карты с разной геопривязкой и отказ от неоднозначного решения |

## 5. Запуск и выходные данные

```bash
python -m pip install -e '.[dev,vision]'
python -m src.synthetic_sensor_bench \
  --output-dir outputs/synthetic_sensor_bench \
  --scenario nominal \
  --frames 6 \
  --seed 72118
```

В `sensors/` записываются PNG-кадры, `synthetic_orthophoto.png`, `imu.csv`, `camera.csv`, `truth.csv`, `calibration.json`, `bench_metadata.json`.

В `evaluation/` создаются `sensor_bench_results.csv` (статус каждого кадра, карта, визуальная скорость, поздняя коррекция РФК) и `sensor_bench_summary.json` (число принятых измерений и RMSE относительно модельной истины).

Все исходные файлы помечены как синтетические. Изменение `--seed` меняет структуру местности и шумы, а неизменный `seed` позволяет повторить расчет.

## 6. Что критерии испытания доказывают, а что нет

Результаты тестирования могут подтвердить:
- правильность геометрической проекции относительно заданной плоской сцены;
- отсутствие подмены поздней временной метки временем приема;
- согласованность направления оптического движения и модели ИИМ;
- отсутствие автоматического слияния ложной картографической привязки;
- отказобезопасное поведение на специально заданных пропусках.

**Они не подтверждают** способность реального БВС длительно зависать без ГНСС на высоте 100 м. В стенде нет реального видео, цифровой модели рельефа, динамики БВС с аэродинамикой/управлением, PX4 SITL-интеграции нового фильтра и независимого метрологического эталона.

Дальнейшие программные этапы без НИИВК: моделирование полного динамического движения в PX4 SITL с синхронизированными виртуальными сенсорами; покрытие временных отказов/вычислительной нагрузки; количественное сравнение навигационных алгоритмов на различных синтетических траекториях и картах. Аппаратное подтверждение является отдельным направлением и не может подменяться результатами синтетики.
