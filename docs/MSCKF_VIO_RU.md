# Тесно связанная VIO (MSCKF) на реальных полетах MUN-FRL

## Что было

VIO была слабосвязанной. VO по паре кадров давала горизонтальную
скорость, причем масштаб брался из высоты (PPK или дальномер), а
15-мерный РФК сливал эту скорость. Ошибка высоты и масштаба VO напрямую
переходила в скорость. На трех полетах MUN-FRL уход составил 4–18 м,
и даже после поправки масштаба по PPK — 1,8–9,6 м
(`docs/REAL_DATA_MUNFRL_RU.md`).

## Что сделано

`src/msckf_vio.py` — MSCKF (Mourikis, Roumeliotis, 2007):

- состояние ошибки: 15 состояний ИИМ (как в `InertialErrorStateFilter`,
  правая ошибка ориентации) и скользящее окно до 10 клонов поз ИИМ на
  моменты кадров;
- обновление по треку признака, который потерян или уходит из окна:
  - триангуляция в параметризации обратной глубины (Гаусс-Ньютон от
    линейной оценки по всем наблюдениям);
  - невязки репроекции с якобианами по клонам и по точке;
  - проекция на левое нуль-пространство якобиана по точке;
  - χ²(95 %) для каждого трека, сжатие QR, одно совместное обновление;
- каждое наблюдение используется один раз: трек, использованный при
  уходе клона из окна, начинается заново;
- **высота, дальномер и PPK фильтром не используются**: масштаб
  наблюдается через ускорения ИИМ.

`src/feature_tracker.py` — KLT с проверкой вперед-назад (0,7 px),
RANSAC по фундаментальной матрице (1 px) и равномерным добором до 150
признаков.

`tools/munfrl_msckf.py` — те же срезы, модель времени ИИМ, сдвиг
камера–ИИМ −37 мс и та же оценка, что у слабосвязанной схемы: курс
кадра Xsens выставляется по первой половине среза, уход и ошибки
скорости считаются по второй.

## Результат

Уход в конце второй половины среза (в скобках — максимум), м:

| | quarry1 (51 м пути) | quarry2 (49 м) | lighthouse (37 м) |
|---|---|---|---|
| только ИИМ | 53 | 61 | 153 |
| слабосвязанная VO + РФК | 4,1 (7,3) | 11,9 | 18,5 |
| то же, масштаб VO по PPK | 1,8 (4,0) | 6,9 | 9,6 |
| **MSCKF, σпикс = 1 px** | **0,38** (1,9) | **1,8** | **0,83** (2,1) |
| MSCKF, σпикс = 0,22 px | 1,2 (2,8) | 3,8 | 7,6 |

| Скорость | quarry1 | quarry2 | lighthouse |
|---|---|---|---|
| слабосвязанная: RMSE, м/с / NEES | 0,97 / 6,6 | 0,85 / 16,2 | 0,84 / 25,0 |
| MSCKF 1 px: RMSE, м/с / NEES | 0,36 / 3,2 | 0,14 / 1,0 | 0,14 / 0,25 |

На кадр использовано 8–14 треков признаков (3500–6300 за срез), по χ²
не отклонено ни одного, по триангуляции отклонено 0–90. Время в
Python — 0,05–0,14 с на кадр.

### Шум пикселя: правило «NIS = 1» не работает

σпикс = 1 px задан до данных. Правило, проверенное на отложенных
полетах: подобрать σ так, чтобы средний NIS на степень свободы у
принятых треков был равен 1. По quarry1 это дает 0,22 px. На quarry2 и
lighthouse с этим σ фильтр **самоуверен** (NEES скорости 15 и 19), и
уход растет в 2–9 раз. Невязки после проекции малы, а ошибку определяет
то, чего модель не содержит: линеаризация при плохо определенной
глубине (база 1 м при дальности 32 м), ошибки синхронизации и внешней
калибровки, затвор камеры. Калибровать σ нужно по согласованности
**оценки** с эталоном (NEES), а не по невязкам.

### Начальная скорость

MSCKF стартует со скоростью от ГНСС (PPK первого кадра, σ 0,3 м/с) —
VIO включается в момент потери ГНСС. Со стартом из нуля (σ 5 м/с, как у
слабосвязанной схемы) quarry2 расходится: уход 920 м. Первые треки с
малым параллаксом через линеаризацию при неверной глубине задают
скорость, и ошибка дальше не исправляется. Со стартом из нуля:

| | quarry1 | quarry2 | lighthouse |
|---|---|---|---|
| уход, м | 0,48 | 834 (расхождение) | 20,3 |

Значит, этой реализации нужна процедура инициализации (неподвижный
старт или выставка по нескольким кадрам). Пока ее нет, MSCKF
запускается только при известной скорости.

Слабосвязанная схема получает скорость прямо из VO, поэтому начальная
скорость на второй половине среза для нее не важна.

## Инициализация без ГНСС

`src/vi_initialization.py`: начальная скорость, смещение акселерометров
и наклон гравитации по трекам признаков и ИИМ за окно 1,5–5 с.

1. Линейный МНК (условие коллинеарности через векторное произведение)
   дает только начальное приближение. Шум направлений лучей
   умножается на неизвестные точки, и решение смещено к меньшему
   масштабу: на синтетике v0 занижена на 2 % при заявленной СКО в 10 раз
   меньше. Со свободным смещением акселерометров масштаб схлопывался.
2. Оценка максимального правдоподобия — Гаусс-Ньютон по ошибке
   репроекции в пикселях. Неизвестные: v0, смещение акселерометров
   (априорно 0,1 м/с²), два угла наклона гравитации (априорно 2°) и
   точки признаков.
3. Опционально — дальность до земли (дальномер): признаки считаются
   точками ровной земли, их глубина по вертикали равна измеренной
   высоте (СКО 5 %).
4. Решение принимается, только если СКО скорости и смещения малы,
   χ²/dof невязок ≤ 3 и, без дальности, разброс ускорения в мировых
   осях ≥ 0,3 м/с². Затем состояние поворачивается так, чтобы гравитация
   была строго вертикальной, и MSCKF стартует с конца окна. Кадры окна
   в фильтр повторно не идут.

**Синтетика:** с дальномером скорость восстанавливается с точностью
0,1 м/с, смещение — 0,03 м/с², наклон — 0,5°. Без дальности за 2 с
горизонтальное смещение и наклон неразличимы (оба дают постоянное
ускорение), и выставка отказывает.

**MUN-FRL** (модуль горизонтальной скорости в конце окна против PPK;
курс в осях Xsens, поэтому сравнивается модуль):

| | quarry1 | quarry2 | lighthouse |
|---|---|---|---|
| PPK, м/с | 0,17 | 1,05 | 2,1–2,2 |
| без дальности | 0,88 (глубина 83 м при 30) | 0,33 (16,5 при 32) | 2,49 (58 при 24,5) |
| с «высотой» PPK вместо дальномера | 0,35 | 0,82 | 1,17 |
| уход MSCKF после выставки без дальности, м | 7,9 | 1,4 | 0,33 |
| уход MSCKF после выставки с «высотой», м | 0,93 | 2,0 | 2,3 |
| уход MSCKF со скоростью от ГНСС, м | 0,38 | 1,8 | 0,83 |

- **Без дальности выставка на этих полетах ненадежна.** Ускорения
  аппарата 0,1–0,3 м/с², и масштаб за несколько секунд не
  определяется: глубины ошибаются в 0,5–3,4 раза. Формальные проверки
  этого не видят: σ скорости 0,05–0,24 м/с, χ²/dof < 1. Разброс
  ускорения 0,44–0,75 м/с² — это вибрации, а не полезное движение, так
  что порог возбуждения тоже не срабатывает. Порог не подбирался по
  этим полетам: иначе это была бы подгонка под данные проверки. MSCKF
  после такой выставки иногда сходится (lighthouse, 0,33 м), а иногда
  нет (quarry1, 7,9 м).
- **«Высота» PPK над точкой взлета — не дальномер.** MSCKF со стартом
  от ГНСС (его скорость совпадает с PPK, масштаб — из ИИМ) триангулирует
  землю на расстоянии:

  | | quarry1 | quarry2 | lighthouse |
  |---|---|---|---|
  | глубина по MSCKF / высота над точкой взлета | 0,92–0,97 | 0,84–1,0 | **2,0–2,1** |

  На lighthouse взлет был с возвышенности, и до земли вдвое дальше.
  Это объясняет и занижение скорости VO на lighthouse в
  слабосвязанной схеме (`docs/REAL_DATA_MUNFRL_RU.md`): масштаб VO там
  брался из той же высоты, а не из фокусного расстояния камеры.
- Вывод для системы: VI-выставка без ГНСС допустима **только с
  дальномером** (настоящая дальность). Проверка на компаньоне с
  дальномером LW20 — `docs/COMPANION_MSCKF_SITL_RU.md`.

## Ограничения

- Три полета и короткие срезы (25–45 с); курс выставлен по PPK первой
  половины (курс Xsens не привязан к северу, а курс VIO ненаблюдаем).
- σпикс = 1 px выбран до данных, но его согласованность подтверждена
  только на двух полетах.
- Внешняя калибровка камера–ИИМ и сдвиг времени не оцениваются в
  фильтре (сдвиг −37 мс найден на quarry1 ранее).
- Затвор, автоэкспозиция и рельеф не моделируются.
- Инициализация без ГНСС — только с дальномером (см. выше).
- Только Python и офлайн; на компаньоне в реальном времени не
  проверялось; в EKF2 не передается.

## Воспроизведение

```sh
python tools/munfrl_msckf.py quarry1:$M/q1 quarry2:$M/q2 lighthouse:$M/lh \
  --pixel-sigma 1.0 --out build/msckf.json
```

Срезы готовит `tools/munfrl_bag_slice.py` (`docs/REAL_DATA_MUNFRL_RU.md`).
