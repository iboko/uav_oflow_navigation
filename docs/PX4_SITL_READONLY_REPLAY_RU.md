# Проверка C++ навигационного модуля внутри PX4 SITL без подмены датчиков

**Результат этапа:** командная диагностическая проверка существующего
C++-ядра `ofnav` внутри исполняемого PX4 v1.16.2 POSIX SITL
на данных синтетических изображений камеры и ИИМ.
**Не является** замкнутой моделью полета БВС и не подключена
к исполнительным органам, EKF2 или внешней одометрии PX4.

## Постановка и выбор способа сопряжения

В проекте имеются две разные экспериментальные реализации:

- Python-контур — калиброванная визуальная одометрия с
  оценкой горизонтальной скорости, отложенная коррекция
  15-мерного РФК и сопоставление с ортофотопланом.
  Проверялся по идеализированной сцене на высоте 100 м.
- C++-контур `firmware/rtos_core` — отдельная 6-мерная
  горизонтальная модель и оценка скорости по **интегральному
  оптическому потоку**, имеющая принятые ранее ограничения
  высоты **0,2–4 м**. Его PX4-модуль через uORB читает
  `sensor_optical_flow`, `distance_sensor`,
  `vehicle_imu`, `vehicle_attitude` и публикует
  только диагностику `debug_vect` при штатном запуске.

Эти два контура **не следует отождествлять**: Python
15-мерный РФК еще не перенесен на NuttX и не включен
в EKF2.

Передавать виртуальные датчики непосредственно в
штатную uORB-шину работающего PX4 опасно для
корректности симуляции: их могли бы принять другие
модули. Вместо этого создана специальная **POSIX-only**
команда `ofnav sitl-replay`. Она вызывает
`FlowVelocityEstimator` существующего C++-ядра с
данными CSV, **не публикует никаких сообщений uORB
и не изменяет состояние полетного контроллера**.
На сборках NuttX команда недоступна.

## Подготовка файлов и шкалы времени

```bash
python -m src.synthetic_sensor_bench \
  --output-dir outputs/synthetic_sensor_bench \
  --scenario nominal --frames 6 --seed 72118

python -m src.export_px4_sitl_replay \
  --results-csv outputs/synthetic_sensor_bench/evaluation/sensor_bench_results.csv \
  --camera-csv outputs/synthetic_sensor_bench/sensors/camera.csv \
  --imu-csv outputs/synthetic_sensor_bench/sensors/imu.csv \
  --output-csv outputs/ofnav_sitl_replay.csv
```

Экспортер получает измеренную алгоритмом VO
скорость N/E, переводит ее через заданный курс
в горизонтальную скорость FRD и затем в
`integrated_x, integrated_y` C++-контура с
использованием высоты и длительности кадра.
**Это математический перевод результатов VO,
а не моделирование реального датчика, выдающего
`OPTICAL_FLOW_RAD`.** Он не использует
`truth.csv` и не знает истинных координат БВС.

Гироскоп и акселерометр берутся строго из строки
`imu.csv` с **точным совпадением времени
экспозиции**. При отсутствии записи ИИМ принятый
кадр не подменяется вымышленным измерением.
Отдельно сохраняются время экспозиции
`timestamp_us` и время получения
`arrival_us`, по ним проверяется свежесть.

CSV включает метки времени, высоту, курс,
`gyro_x/y/z`, `accel_x/y/z`,
`flow_x_rad`, `flow_y_rad`,
`integration_dt_s`, качество и флаг
пригодности. Недоступный кадр явно отмечается
`flow_valid=0`, не рассматривается как нулевое
движение с достоверным оптическим потоком.

## Запуск внутри PX4 SITL

Для PX4 v1.16.2:

```bash
bash tools/install_px4_ofnav_module.sh PX4-Autopilot boards/px4/sitl/default.px4board
make -C PX4-Autopilot px4_sitl_default

bash tools/run_px4_sitl_replay_smoke.sh \
  PX4-Autopilot \
  outputs/ofnav_sitl_replay.csv \
  outputs/px4_sitl_logs
```

Скрипт запускает PX4 в POSIX-режиме
`PX4_SIM_MODEL=shell` без Gazebo/физического
движения БВС, затем вызывает **внутреннюю
C++ команду PX4**:

```text
ofnav sitl-replay /absolute/path/ofnav_sitl_replay.csv
```

Проверяется чтение CSV, строгий порядок времени,
границы параметров и причина отклонения.
Обязательная проверка безопасности для данных
100 м: **accepted=0, height_rejected>0**.
Если хотя бы одна запись на высоте свыше
4 м принята, процесс завершается с ошибкой.
Это ожидаемый результат, **не провал** алгоритма
низковысотной диагностики.

Результаты сохраняются в
`px4_sitl_boot.log` и
`ofnav_sitl_replay.log`; GitHub Actions
собирает PX4 и публикует оба файла вместе с
CSV в `px4-sitl-read-only-synthetic-replay`.

## Что не выполнено этим этапом

- В PX4 **не выполняется** новая отложенная
  15-мерная визуально-инерциальная коррекция.
- C++-ядро **не разрешено** использовать на
  высоте 100 м: его границы сохраняются.
- Не подключены модели камеры/ИИМ через
  симулятор Gazebo/SIH с динамической моделью
  БВС; команда `sitl-replay` — внутрипроцессная
  диагностическая процедура без замкнутой динамики.
- Не разработана безопасная передача
  картографических измерений в EKF2/PX4.
- Не подтверждены задержки, ковариации,
  метрологическая точность или способность
  реального БВС к зависанию без ГНСС.

**Следующий этап после подтверждения этой проверки:**
перенос фиксированной истории 15-мерного РФК
в отдельную диагностическую архитектуру C++ и
отдельная динамическая PX4 SITL-модель виртуальных
датчиков с явно изолированной диагностической
шиной и доказанной системой временных меток.
